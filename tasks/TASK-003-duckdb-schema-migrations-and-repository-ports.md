## Persistence policy

- The database path comes from one typed, documented environment setting. Its default must be safe for local development and must not point inside source code.
- The database file, write-ahead log, raw data, and artifacts are ignored by version control.
- The application creates its parent data directory only after explicit configuration/startup behavior is defined and tested.
- Open connections are scoped and closed predictably. Do not share a global mutable connection across requests without a documented lifecycle.
- All SQL is parameterized. Identifiers are application-owned constants, never client input.
- Store timestamps in UTC and represent date-only business values as dates. Do not use local machine timezone implicitly.
- Store currency/money values as strings/decimal-compatible representation with currency code when introduced later; this task should not create money columns.

## Initial schema

Implement ordered migrations and a schema ledger. The initial migration creates only these tables and constraints. Names may use the project’s established naming convention if documented consistently.

### `schema_migrations`

| Column | Requirements |
| --- | --- |
| `version` | Integer primary key; corresponds to one ordered migration file. |
| `name` | Non-empty migration identifier. |
| `applied_at_utc` | UTC timestamp. |
| `checksum` | Checksum of applied migration contents; used to detect edited history. |

### `datasets`

Represents a versioned data collection, not its bars.

| Column | Requirements |
| --- | --- |
| `dataset_id` | Opaque UUID/string primary key generated by application. |
| `version` | Positive integer; unique with a stable logical dataset key if that key is introduced. |
| `name` | Non-empty human-readable name. |
| `source_name` | Non-empty provenance source label. |
| `source_reference` | Optional safe provider/file reference; never credentials. |
| `license_reference` | Optional license/terms reference. |
| `content_checksum` | Required checksum of imported source/normalized input when known; bootstrap may use a documented placeholder only in tests. |
| `bar_interval` | Required declared interval (for example `1d`); no bar rows are stored yet. |
| `timezone` | Required IANA timezone or documented UTC representation. |
| `adjustment_policy` | Required explicit enum/string; do not default silently. |
| `coverage_start_date` / `coverage_end_date` | Optional dates, must be chronological when both exist. |
| `created_at_utc` | Required UTC timestamp. |
| `validation_status` | Required explicit state: `pending`, `valid`, `warning`, or `rejected`. |
| `validation_summary` | Optional non-sensitive text/JSON summary. |

### `backtest_runs`

Represents an immutable run identity and manifest envelope, not result artifacts.

| Column | Requirements |
| --- | --- |
| `run_id` | Opaque UUID/string primary key generated by application. |
| `dataset_id` | Required foreign-key-like reference to `datasets`; enforce referential integrity if supported. |
| `strategy_spec_version` | Required non-empty version/reference; strategy content is not stored yet. |
| `engine_version` | Required non-empty adapter/engine version reference. |
| `configuration_json` | Required JSON/text manifest field; exact schema is owned by TASK-006. |
| `status` | Required explicit state: `created`, `running`, `completed`, `failed`, or `cancelled`. |
| `created_at_utc` | Required UTC timestamp. |
| `started_at_utc` / `finished_at_utc` | Optional UTC timestamps, chronological when present. |
| `warning_count` | Required non-negative integer. |
| `failure_code` | Optional stable safe error code; never stack trace. |

### Constraints and indexes

- Enforce primary keys, required fields, allowed status values, non-negative warning count, and temporal ordering using database constraints where DuckDB supports them; otherwise validate in domain/application code and test it.
- Add only indexes justified for lookups by primary key, `dataset_id`, and creation time.
- Do not use database-generated timestamps or random IDs where that would impair test determinism; generation belongs at the application boundary.

## Repository ports

Define application-layer protocols/interfaces without DuckDB types or SQL. Keep methods narrowly aligned to current needs:

```text
DatasetRepository
  create(dataset: DatasetManifest) -> DatasetManifest
  get(dataset_id: DatasetId) -> DatasetManifest | None
  list(filters, page) -> Page[DatasetManifest]

BacktestRunRepository
  create(run: RunManifest) -> RunManifest
  get(run_id: RunId) -> RunManifest | None
  transition_status(run_id, expected_status, next_status, timestamps, failure_code?) -> RunManifest
```

The port must make immutability explicit: manifests cannot be overwritten; status transitions use compare-and-set semantics and reject invalid transitions. Define a small transition policy (`created → running → completed|failed|cancelled`) in domain/application code, while leaving actual run execution to later tasks.

Do not expose generic CRUD, database connections, raw query strings, or engine types through ports.

## Migration runner behavior

1. Discover migrations in strict numeric order from an application-owned location.
2. Reject duplicate numbers, malformed names, checksum mismatch for an applied version, gaps when policy requires contiguity, and an unknown newer database version.
3. Apply each unapplied migration once and record its version/name/checksum/applied time atomically where possible.
4. Be idempotent: a second run against the same valid database makes no schema change.
5. Emit structured migration logs without SQL values or filesystem secrets.
6. On failure, preserve a diagnostic error with migration version/name and fail closed—never mark a partial migration as applied.

## API addition

Add `GET /api/v1/ready` only after migration initialization is available. It returns `200` with the standard service/version fields and a `database: "ready"` field when the configured database is accessible and up to date. If unavailable or migration fails, return a safe `503` envelope with code `dependency_unavailable`, correlation ID, and no filesystem path or connection detail.

Keep `/health` dependency-free and unchanged. This readiness endpoint must not initialize a database on every request; lifecycle semantics belong in a tested application startup/dependency design.

## Test plan

Use a temporary database per test; never write to a user path. At minimum test:

1. A new database receives every migration in order and records matching migration ledger entries.
2. Rerunning migrations is idempotent.
3. A changed checksum for an already applied migration fails closed.
4. Duplicate/malformed/future migration versions fail with actionable, safe diagnostics.
5. `datasets` accepts a valid manifest and rejects missing required fields, invalid status, invalid dates, and non-explicit adjustment policy.
6. `backtest_runs` requires a known dataset, preserves its immutable manifest fields, and validates status transitions including concurrent/stale expected state.
7. Repository implementations satisfy port behavior without exposing DuckDB classes to application/domain tests.
8. `/health` remains database-independent; `/api/v1/ready` returns the documented ready and unavailable behavior.
9. Test suite can run entirely offline and cleans up temporary files.

## Acceptance criteria

- The schema/migration policy follows ADR-002 and is documented with actual file/path conventions.
- Migration execution is ordered, idempotent, checksum-protected, and fails closed for incompatible state.
- Dataset and run-manifest tables/ports enforce the stated constraints without storing market bars or result artifacts.
- Repositories are behind application ports; SQL/DuckDB types do not cross the infrastructure boundary.
- The readiness endpoint accurately distinguishes database availability from process liveness and does not leak paths/secrets.
- All migration, repository, API, formatting, linting, strict type-checking, and tests pass.
- Project memory/task index/this task’s handoff record only verified behavior and commands.
